## 六角色真实流程

使用独立运行目录、独立身份与公共开发 CRS，在一台机器启动两个客户端、两个边缘节点、两个云节点，通过真实 HTTPS RPC 执行。数据为本机缓存的真实 MNIST，训练 1,200 张、测试 200 张，8×8 池化线性模型 650 坐标；两轮、每轮两个本地 epoch、seed 42、IID、无攻击。分别执行明文、CPU 密码计算和 GPU 密码计算，三次运行源码指纹相同。

三组逐轮模型摘要与批准客户端集合完全一致。使用 TensorBoard 原生 `EventAccumulator` 读取事件文件：全局准确率/损失步数均为 `[0, 1, 2]`，两个客户端的叠加指标步数均为 `[1, 2]`。客户端指标来自各自本地训练集，不能与全局测试集指标混为同一评估集。六个节点均有独立监控条目，采样器正常清理，实测结束后六个隔离进程均已停止。GPU 组主控真实执行 24 个密码内核批次、17,030 行，另有两个授权节点完成 GPU 准备与执行；不只是读取显卡状态。

GPU 兼容性验证范围为 RTX 4070 Laptop（SM 8.9）、NVRTC 包 12.9.86、驱动接口 12070。修改前实际内核加载返回 222，修改后新进程精确自检通过。CUBIN 的使用依据 [NVIDIA 小版本兼容说明](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)及 [NVRTC 文档](https://docs.nvidia.com/cuda/nvrtc/)，不能由这一次验证外推到所有驱动、平台或 GPU 型号。

这是功能正确性验收，使用小样本、单个 seed，且同机有其他验证工作；耗时不用于速度提升结论，也不是论文规模、三机、攻击鲁棒性或模型精度基准。原生密码扩展在独立验证环境按当前 Rust 源码构建；原有应用环境及运行目录未改动。

配置、曲线读数、节点计数、运行源码及原生二进制指纹见[机器可读验收记录](evidence/review-improvements-20261011.json)。三次运行的原始结果文件摘要也已记录；历史验收目录中的既有结果没有重写。
