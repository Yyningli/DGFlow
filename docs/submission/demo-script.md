# 演示脚本

本脚本用于展示可复验的研究原型，不预设成功率、准确率或耗时。所有台词中的数字应从现场任务或附带实测 JSON 读取。不要把建议配置、截图、单机记录写成三机实测结果。

## 演示前准备

按[部署说明](deployment.md)准备 Python 依赖、已校验的 MNIST 缓存和 `web/dist`。提前运行 `doctor` 并检查节点日志。若现场离线，先用离线启动模式实际验证，不依赖临场下载。

准备一组相同种子、相同数据上限、相同训练轮数、相同本地轮数的历史任务；用于对照的攻击设置也保持一致。至少保留正常运行、异常输入和可用性边界的记录。记录仍在计算时，可以先展示已完成记录，并明确标记“历史实测”；不能播放曲线动画冒充实时计算。

`screenshots/` 中的截图记录的是早期界面版本。重做界面后如需展示当前入口，应从实际运行页面重新截图；它们只用于说明界面与连接状态，不是性能证据，也不是获奖或三机部署证据。更新截图应直接取自实际运行页面，不拼接虚假指标。

## 2. 运行一轮实际协议

在“部署”页选择 DGFlow 或优化调度模式，先设置 1 个全局轮次，使用已验证可承受的样本量和本地轮数。现场解释这些是训练配置，不是安全参数强度的完整描述。确认“启动前检查”四项均为就绪后点击“运行 DGFlow”。

展示真实事件顺序：健康检查与数据准备、任务首轮全员 DKG、本地训练与加密证明、归属边缘接收并核验客户端提交、共享签名结果及共同筛选授权、云门限聚合、完成轮次。后续轮复用任务密钥周期。某阶段尚未出现时保持等待，不声称已经通过。

若计算时间超出现场展示窗口，可保持任务运行，切换展示已保存的相同配置历史实测，并明确说出切换；不截断密码过程后补造完成标记。

## 3. 解释验证为什么通过或失败

打开“验证”页，逐项说明证明校验、公开评分、接纳决定和后端理由。正常任务完成后，可另建一个证明篡改或符号翻转任务，也可选择已完成的对应历史任务。

证明篡改演示验证拒绝路径；符号翻转演示对预设模型攻击的筛选表现。两者证明的事情不同。现场表述应为：

> 本次任务中，系统对这些提交给出了这里记录的决定。范围和平方范数关系通过，不意味着没有投毒；我们还要看统计筛选、诚实客户端误杀和最终模型结果。

指明“未接纳客户端”包含批次连带排除，并解释固定批次的诚实成员可能受牵连。若验证记录已返回但本轮模型未发布，明确说明这是阶段证据，不是训练成功。

## 4. 展示聚合门限边界

使用“部署”页的“本轮排除聚合节点”设置，说明这是**逻辑排除**。这些节点的服务仍可在线或上报遥测，不能解释为“宕机后自动恢复”。TensorBoard 中出现该节点的资源指标不代表它参与了本轮聚合。

- 排除 v−e 个：剩余 e 个云恰好满足已配置门限，检查其他前提满足时是否完成合法聚合，结果以实测为准。
- 排除 v−e+1 个：剩余云少于 e，后端应拒绝启动或发布模型，保留实际错误。新默认 e=2、v=4 时对应排除 2 个与 3 个；旧 2/3 配置对应排除 1 个与 2 个。

补充说明：新任务 DKG 仍需要全部 w 个边缘参加，主控还是 RPC 转发及编排单点。若希望展示实际进程崩溃，必须另有真实故障注入、时点和恢复记录，不能用这个开关替代。整台物理机器退出同时影响多个角色，也不是本开关模拟的情况。

## 6. 展示证据与退出

导出一份实验 JSON，核对配置、轮次、事件和汇总字段。展示设计报告中的实测证据索引，保留开源依赖与参考论文归属。正式材料中的性能数字由实测报告提供，不在台词中手填未经验证的提升比例。

如果任务仍在运行，点击停止后等待后端确认；结束控制服务后按部署说明停止节点进程。演示失败时展示真实错误、说明当前限制并保留日志，不把失败任务截图替换为成功样例。

## 问答要点

| 问题 | 应准确回答的边界 |
| --- | --- |
| 数据是否真的来自多个机构？ | 当前为公开 MNIST 的本地分区重放，不是真实机构数据。 |
| 加密后是否完全不泄漏？ | 不是；范数、授权内积、评分和聚合模型是允许输出。 |
| 证明通过是否排除投毒？ | 不能；证明约束关系一致性，投毒还涉及训练语义与统计判定。 |
| 任意一台主机掉线后都能训练吗？ | 不能如此声称；s/w、e/v恢复条件与新任务DKG全员参加、分组策略及主控单点需分别讨论。 |
| 改进策略一定更快、更准确吗？ | 只有相同配置的实测才能支持具体结论，不能从并行代码直接推出。 |
| 是否已用三张GPU完成加速？ | 依据任务实际设备、能力协商及对应记录回答；本机GPU记录不能当作三张GPU或三机实测。 |
| 三机部署完成了吗？ | 部署路径和分包工具已提供；没有实际三机验收记录时，明确说尚未完成物理环境实测。 |
