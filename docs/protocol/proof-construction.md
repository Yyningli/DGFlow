# 密文、发放密钥与整数范数的一致性证明规格

版本：研究实现规格 v0.1，2026-10-01 起；后续方案按章节保留。

当前入口说明：新建 `encrypted`、`dgflow`、`optimized` 实验仅接受第 15 节的 `lego_norm_v1`，必须预先安装匹配维度、位宽及指纹的 CRS；`plain` 不生成证明且无需 CRS。第 1–14 节中的旧逐位 OR、5A/5B 方程及测量属于历史方案，保留用于研究核对，不代表当前默认。完整部署可准备本地单方开发 CRS，角色及实验启动本身不执行设置。

状态：已完成方程级审查、一手来源核对和相应实现；实际测试结果以提交包中的验收记录为准。尚未完成教师或独立密码学专家的外部审查，也没有对本系统组合给出新的完整安全定理。本文不构成安全认证，测试通过不能替代协议审查。最终接口与早期规格的明确化见 `protocol-v1.md`。

> **线格式修订**：G1/G2/标量/GT 现以原始字节（48/96/32/576 字节）参与规范二进制编码，不再使用十六进制字符串；`digest`、`hash_point`、`challenge` 均对该二进制编码取摘要（`transport/binary.py` 的 `packb`）。**本文的方程与关系一字未改**，但所有上下文/清单/证明摘要、加密底数 `f` 与 Fiat–Shamir 挑战的取值随之改变，因此修订前后的记录不能做哈希级对比。详见 `protocol-v1.md` 的修订记录。

本作品依据本地 DGFlow 论文重建 DMAFE。论文没有给出可直接复用的完整 NIZK 转录。本文选择公开文献中的 Pedersen 承诺、表示知识证明、乘法关系证明和 Schnorr OR 组合，补齐一条具体实现路线；不能将本文描述称为 DGFlow 原作者的证明实现，也不声称提出新的 FE 或证明原语。

## 1. 目标与明确不覆盖的性质

对于同一客户端、本轮唯一提交的向量，证明：

1. 每个密文使用该客户端从已确认 DKG 得到的实际秘密。
2. 每个密文中的整数与范围证明、平方承诺中的整数相同。
3. 每个整数处于指定的有符号区间，公开平方范数是这些整数的平方和。
4. 证明绑定指定任务、轮次、密钥周期、模型与编码参数，不能直接移植到另一提交。

本证明不证明输入由真实本地数据训练得到，不证明没有投毒或后门，不证明筛选算法、函数钥发放策略、完整 DMAFE、门限解密及网络协议的组合安全。范数与获授权内积仍属于系统主动公开的信息。

## 2. 群、编码和假设

采用 BLS12-381 的素数阶子群 G1、G2 和配对目标群 GT。本文统一用乘法记号表示群运算；实现中的 G1/G2 接口通常使用点加法与标量乘法。令 q 为这些子群的阶，即标量域模数。**q 不是 BLS12-381 坐标基域的素数。**

- g 是 G1 固定生成元，h2 是 G2 固定生成元。
- H 是独立的 G1 Pedersen 基点。使用固定套件和域分离的标准 hash-to-curve 导出，且无人知道 log_g(H)。
- f 是该轮所有客户端共同使用的加密底数，以独立域分离从共同加密标签 hash-to-curve 得到。加密标签遵循系统设计，不能因客户端身份不同而改变 f。
- g、H、f 必须为正确素数阶子群的非单位元。所有外部点必须使用规范编码并检查曲线和子群成员资格。实现中的网络编码为压缩点原始字节（G1 48、G2 96 字节），解码时校验长度、重新编码一致性与子群成员资格；标量为 32 字节大端且必须小于 q。
- 不得以 g * hash_to_scalar(public_label) 构造 H：这种方式公开了两个承诺基点的离散对数关系，使绑定失效。
- 所有秘密、承诺掩码及证明随机数属于 F_q，由密码学安全随机源生成。训练随机种子不能用于密码随机数。
- 有符号整数的标量表示为 x mod q；网络中的整数范数和编码参数仍按整数解析，不能先模 q 后再检查合法性。

所依赖的边界包括离散对数困难性、正确的 hash-to-curve、Fiat–Shamir 的随机预言机解释、规范转录及密码随机性。本文不声称标准模型安全、抗量子安全或 Python 实现的常数时间性质。

## 3. DKG 必须提供的绑定对象

对客户端 i、坐标 j、密钥周期 epoch，DKG 除分发 s_ij 的份额外，还用独立盲化多项式分发 k_ij 的份额，形成：

    K_ij = g^(s_ij) H^(k_ij)

各参与者的多项式系数 Pedersen 承诺经过份额验证后组合，常数项承诺的乘积就是 K_ij。客户端只重构自己的 s_ij、k_ij。验证者从**已确认且不可变的 DKG 转录**获取 K_ij，不能接受客户端在证明中自行指定的新 K_ij。

需要分别验证：

- 每个收到的秘密份额与对应的公开系数承诺相符。
- 最终参与集合、系数承诺、客户端/坐标索引和密钥周期的转录摘要一致。
- 客户端重构得到的 s_ij、k_ij 确实满足已发布的 K_ij。
- 各密钥节点保留的 s_ij 份额正是后续生成函数钥所用的份额。

私信渠道须同时具备机密性与认证；签名只能提供认证，不能保护明文秘密份额。当前工程边界是固定成员、认证通信和崩溃/异常时中止；不宣称简单 HTTP 群发实现恶意网络的一致广播、完全恶意 DKG、偏置抵抗或拜占庭可用性。不一致时不能由控制服务单方面选一份转录继续。

**禁止公开 h2^(s_ij)**。它会使持有密文的观察者通过配对消除单坐标掩码：

    pairing(ct_ij, h2) / pairing(f, h2^(s_ij)) = pairing(g,h2)^(x_ij)

而本文的 K_ij 是带独立未知掩码的 G1 Pedersen 承诺，不是上述解密辅助量。本文没有证明把这些额外承诺加入 DMAFE 后的完整系统归约；这仍需外部审查。

## 4. 每个客户端的公共关系

省略客户端和轮次下标，维度为 d，坐标 j = 0,...,d-1。设 b 是有符号量化位宽，o = 2^(b-1)，要求：

    -o <= x_j <= o-1
    ct_j = f^(s_j) g^(x_j)
    K_j  = g^(s_j) H^(k_j)
    C_j  = g^(x_j) H^(r_j)
    D_j  = g^(x_j^2) H^(t_j)
    Xi   = sum_j x_j^2                 （整数）
    T    = sum_j t_j mod q
    product_j D_j = g^Xi H^T

K_j、ct_j、C_j、D_j、Xi、T 以及范围承诺均为公共实例的一部分。s_j、k_j、x_j、r_j、t_j 为见证。

Xi 是平方范数，不是范数。T 只公开平方承诺掩码的总和，**不得公开各个 t_j**；各个 t_j 一旦公开，小整数平方可能被枚举。维度为 1 时 Xi 本身就是 x_0^2，本协议不会隐藏这一本来已公开的信息。

## 5. 位范围证明及与 C 的精确绑定

令 v_j = x_j + o，写成恰好 b 位：

    v_j = sum_l 2^l beta_jl,  beta_jl in {0,1}
    B_jl = g^(beta_jl) H^(rho_jl)
    C_j  = g^(-o) product_l B_jl^(2^l)
    r_j  = sum_l 2^l rho_jl mod q

每个 rho_jl 独立均匀。验证者必须直接检查上述 C_j 重构关系；不能只证明一组无关的 B_jl 是比特。若希望先独立选取 C_j 的随机数，则须另加正确的等值/重盲化知识证明；初版不要采用该变体。

对每个 B，证明知道下列一个离散对数：

    Y_0 = B       = H^rho         （beta = 0）
    Y_1 = B / g   = H^rho         （beta = 1）

采用标准 Schnorr OR：

1. 对未知分支 u = 1-beta，随机选择 e_u,z_u，计算 A_u = H^(z_u) / Y_u^(e_u)。
2. 对已知分支 beta，随机选择 w，计算 A_beta = H^w。
3. 收齐全部坐标的首消息后计算全局 Fiat–Shamir 挑战 e。
4. e_beta = e-e_u mod q；z_beta = w+e_beta*rho mod q。
5. 验证 e_0+e_1 = e mod q，且对 c in {0,1} 均有 H^(z_c) = A_c Y_c^(e_c)。

可以在所有 AND 子证明中共享全局 e，但**OR 的两支挑战之和才是 e**。不能把每一支都设置成 e，也不能把比特明文作为分支标记公开。

## 6. 联合表示和平方关系的首消息与响应

对每个坐标独立随机选取 u_j,v_j,a_j,b_j,c_j in F_q，生成：

    A_ct,j = f^(u_j) g^(a_j)
    A_K,j  = g^(u_j) H^(v_j)
    A_C,j  = g^(a_j) H^(b_j)
    A_D,j  = C_j^(a_j) H^(c_j)

对全局挑战 e，响应为：

    z_s,j = u_j + e*s_j
    z_k,j = v_j + e*k_j
    z_x,j = a_j + e*x_j
    z_r,j = b_j + e*r_j
    z_t,j = c_j + e*(t_j-r_j*x_j)      （全部模 q）

验证者逐坐标检查：

    f^(z_s,j) g^(z_x,j) = A_ct,j ct_j^e
    g^(z_s,j) H^(z_k,j) = A_K,j K_j^e
    g^(z_x,j) H^(z_r,j) = A_C,j C_j^e
    C_j^(z_x,j) H^(z_t,j) = A_D,j D_j^e

这里同一个 z_s 连接密文与实际密钥承诺，同一个 z_x 连接密文、数值承诺和平方承诺。第三、四式是已知 Pedersen 乘法关系证明在同一被乘数上的平方特例；其代数对应文献中的 C1=C2 的情形。该简化与其同范围 OR 证明的组合仍须审阅，不能仅引用文献就声称完整组合已被证明。

**共享响应只发生在上述同一坐标的同一联合关系中。** 不得跨坐标复用 a_j、u_j 等随机数，不得跨证明或不同挑战复用首消息。跨坐标复用 a 时，两个 z_x 的差可能直接暴露整数差；跨挑战复用同一首消息会暴露见证。

## 7. Fiat–Shamir 转录与格式

e 必须由规范编码的完整公共实例和全部首消息导出。至少包括：

- 协议版本、曲线/哈希套件、域分离字符串；
- task_id、round_id、key_epoch、client_id、model_hash；
- quantization_id、d、b、整数范数上限和策略摘要；
- 已确认 DKG 转录摘要，以及按坐标排列的 K_j；
- g、H、f 的规范编码或固定且可验证的套件标识；
- 全部 ct_j、C_j、D_j、B_jl，公开整数 Xi 和标量 T；
- 全部 A_ct,j、A_K,j、A_C,j、A_D,j 和所有 OR 分支 A_0,A_1。

最后使用一个规范定义的 hash-to-scalar 算法得到 e in F_q，例如 SHA-512 对完整规范转录的摘要按大端整数解释后模 q；具体版本必须固定。这里得到的分布偏差极小，但不称为精确均匀。不能把32字节整数简单截断为不足安全长度的挑战。

响应不进入生成自身挑战的首轮哈希。实现既可显式序列化首消息，也可按文献规定从响应重构；初版优先显式格式，便于独立检查。

格式要求：

- 使用带版本、类型、数量及长度边界的规范二进制格式。**已按此实现**：`transport/binary.py` 定义自描述的紧凑编码（9 种标签、varint 长度、字典键按 UTF-8 字节排序），并严格拒绝未知标签、超长 varint、非规范长度、非法 UTF-8、非字符串或重复或乱序的字典键、尾随字节以及深度与长度超限。摘要与 Fiat–Shamir 转录直接对该编码取字节，不再依赖普通字典显示顺序或语言对象 repr。
- 不接受未知尾随数据、重复字段、非规范整数、非规范点或超过配置的向量/证明长度。
- 标量均为 [0,q-1] 的固定长度编码，不能通过模约简悄悄接受超范围响应。
- 验证者从任务状态获取预期实例，不依赖证明自报的身份、密钥、上界、轮次或量化参数。
- 加密 f 对所有客户端相同；client_id 单独绑定进证明和认证消息，不放入每客户端不同的 f。
- 不把所有点的单位元一概判为不合法：Pedersen 承诺或首消息理论上可为单位元。基点不得为单位元；其他点按具体关系检查。

## 8. 从有限域关系到整数范数

范围证明将每个 x_j 约束在 [-o,o-1]，但群方程本身只约束模 q 的值。初始化至少检查：

    2^b < q
    d*o^2 < q
    0 <= Xi <= min(configured_norm_square_bound, d*o^2) < q

在这些充分条件下，合法整数平方和不会回绕，公开 Xi 可按整数解释。不要只检查 Xi 小而省略逐坐标范围。

若参考向量满足 |z_j| <= B_z，最多 N 个客户端以整数权重 |y_i| <= B_y 聚合，还须检查：

    2*d*o*B_z < q
    2*N*o*B_y < q

这是符号恢复的充分界限，不是性能界限。实际还需为内积 [-d*o*B_z,d*o*B_z] 和聚合 [-N*o*B_y,N*o*B_y] 分别配置可负担的有界 DLP 区间。失败时明确拒绝/中止，不能返回模意义下的“近似正确值”。

如果使用更紧的公开范数上界减少 DLP 搜索范围，必须证明该上界正确地约束目标函数并在所有相关输入上强制执行；不能为了加速临时缩小表而遗漏合法输出。

Xi=0 是合法零向量的情况；余弦分母为零必须由筛选策略明确处理。不能以除零异常或伪造相似度替代策略。

## 9. 方程级审查结论及泄漏分析

**代数完整性：已检查。** 第四式展开后，r_j*x_j 项在响应中抵消，得到要求的 D_j^e；其余三式为标准表示知识关系。

**知识绑定的检查思路：有标准依据，组合外部审查未完成。** 对相同首消息、不同挑战的接受转录，响应差可提取 s,k,x,r 和 t-r*x；结合第三、四式获得平方承诺的一个开口。OR 提取获得每个位承诺的比特开口。若两条路径得到不同的 x、或 K 中提取的 s 不同于已发放 s、或声称的 Xi 不同于提取平方和，则与同一 Pedersen 承诺的计算绑定产生冲突。这里陈述检查思路，不把它写成已发表或已审核的归约。

**零知识的检查思路：有标准依据，不能扩大表述。** 给定公共实例及挑战，可以选择均匀响应并由验证等式反算首消息；OR 采用标准模拟。T 是随机 t_j 的和；各 D_j 的联合分布在约束乘积后只显式打开 Xi。该分析针对新鲜独立掩码和既定公共泄漏，不意味着 Xi、授权内积及跨轮全局模型不泄露训练信息。

额外风险：

- 对同一秘密与标签提交不同 x 会产生可消去掩码的密文比值。状态机须使每客户端每轮提交唯一且不可变；重试原提交不得变更内容。
- 证明密钥一致性不能限制验证者发起任意函数请求；函数允许集合、一次授权、轮次锁定需由节点独立执行。
- 范数和比特证明规模为 O(d*b)。先在16维向量及650参数模型测量，不能把结果外推为百万参数可用。
- Python 大整数、分支、内存复制及底层接口未经过常数时间审计。研究演示不等于抵抗本机侧信道的部署实现。

## 10. 实施前与实施后验收

实现前须由另一名成员按本文独立核对关系、转录字段、负数表示和 q 的来源。正式报告保留“教师/外部密码学审查未完成”的状态，直至实际完成审查。

实施后的最小测试：

1. 合法向量：零、正负混合、上下边界、最大合法整数范数；与整数明文计算精确一致。
2. 分别篡改 ct、K、C、D、Xi、T、位承诺、任一响应，均应拒绝。
3. 使用别的有效 DKG 密钥或客户端、改变 task/round/epoch/model/量化/维度/上界，均应拒绝。
4. 范围外 x、把整数加 q、仅有模平方和成立的伪造输入，均不得通过整数策略。
5. OR挑战和错误、缺位、多位、坐标重排、额外尾数据、无效子群点、过长消息均拒绝。
6. 测试同一合法公共实例的独立证明具有新鲜首消息；不得记录或返回见证/证明随机数。
7. 增设本地测试专用的可控挑战接口，可对同一首消息生成两条测试转录，检查响应差提取与预期见证相符；该接口不得进入生产证明API。
8. DKG 份额不一致、参与集合不一致、发钥门限不足以及通道认证失败时中止，不签发一个表面有效的授权。

## 11. 当前底层库的关键接口陷阱

研究期间核对了 py_arkworks_bls12381 0.5.0 的已发布源码及 Windows wheel 元数据，并已用该后端执行真实配对、密码测试和多进程联邦训练。下列事项是实现时已经处理、仍需使用者理解的接口差异。

- G1Point()/G2Point() 是生成元，point * Scalar(n) 是标量乘法。
- GT.pairing(g1,g2) 返回包含最终幂运算的结果。GT.one() 是乘法单位元。
- GT 支持乘法、相等和哈希；str(gt) 是完整规范序列化十六进制。实现路径是 `gt_dump` 把它转为 576 字节原始字节、`gt_load` 通过 Fp12 线性基还原并核对重新编码与非零子群条件；`repr(gt)` 会截断，不能使用。
- GT 没有公开的 pow/inverse/to_bytes/from_bytes 接口；对已确认位于阶 q 子群的值，使用平方乘，并将负指数模 q。
- **-gt 是扩域加法取负，不是 GT 乘法逆。GT.zero() 也不是乘法单位元。**
- 不能用 Python 对象 hash 值代替网络认证摘要或跨进程规范序列化。
- 跨进程接收 GT 时，必须制定且实现可核验的编码/解码路线；当前绑定缺少公开GT反序列化接口，不能以 repr、pickle 或假GT占位绕过。单进程测试通过不代表网络协议已具备该能力。

## 13. 2026-10-03 的 5A / 5B 实验性证明套件

前述逐位构造继续由 `proof_suite=legacy` 执行。新增套件显式选择，不将旧记录迁移到新证明。两种新套件都使用 **BLS12-381 G1、同一 G/H**，生成器以独立域分离 hash-to-curve 导出；没有用另一条曲线的范围证明代替本曲线承诺的关系。

| 套件 | 范围/范数关系 | 保留的一致性关系 |
| --- | --- | --- |
| `compact_range_v1`（5A） | 聚合范围证明验证 `C_j+oG` 的开口在 `[0,2^bits)`；保留逐坐标 `D_j` 和平方关系 | 密文、注册密钥、C、D 的原四个 Sigma 方程 |
| `compact_norm_v1`（5B） | 每块专用二次 IPA 证明同时约束 C 的整数范围和 `S_k=G·Σblock x_j²+H·t_k` | 密文、注册密钥、C 的三个 Sigma 方程，共享同一 `z_x` |

5B 验证 `ΣS_k=Xi·G+T·H`，只公布 `T=Σt_k`，不公布单块平方和或单块盲化。真实坐标按不可变块布局恰好覆盖一次，辅助 padding 仅增加位约束，不增加输入或平方和。整个维度仍执行 `2*d*o²<q` 及整数范数界限。删除逐坐标 D 以后，范数关系由绑定同一 C/S 的完整二次多项式和 IPA 承担。

`compact.py` 写出二次扩展的 M、V、delta 和 `t0` 推导，`ipa.py` 实现完整对数轮数的内积论证。5B 是本项目的**实验性专用二次扩展**，不是已审计的通用 committed R1CS 库。方程复核、恶意见证测试与内部独立审查均不能自动继承其他 Bulletproofs 实现的安全定理；知识提取、Fiat–Shamir 组合和侧信道性质仍需密码学外部审查。

全局转录无循环：先固定全部 C/D 或 C/S、Sigma 首消息、公开范数、注册密钥、密文、上下文和真实块布局；各块证明绑定此全局摘要及块序号/起点/长度；外层挑战再绑定有序完整块证明；最后生成 Sigma 响应。新套件的 `proof_suite`、`proof_block_size` 必须进入轮次上下文，任务策略持久固定套件和验证方式，验证器不做套件降级回退。

## 14. 验证和原生计算加速的边界

`verification=deterministic` 逐方程校验；`randomized` 在受检点/规范标量/字段/挑战和范数检查完成后，为各个群残差采样独立均匀非零系数并做大 MSM。对一个在采样前固定、至少一个残差非零的输入，单次加权检查的误接受概率至多 `1/(q-1)`，N 次独立批验的联合上界为 `N/(q-1)`；约为 255 位群阶量级。失败后确定性复查对应客户端。该随机化只合并原方程，不缩短证明；5A/5B 的块证明本身仍逐块确定性验证。

可选 `dgfl-native` 提供 Arkworks GT 规范解码、非零与阶 q 子群检查、原生幂和逆元。未安装时回退至前述 Python/Fp12 路线，验证关系不变。负小指数通过原生逆元后取正幂，不把 `-GT` 当逆元。公开 G/H 查表只用于验证响应等公开系数，不用于秘密见证或随机数。任何外部 G1/G2 点仍须受检解码。

验证进程使用 Windows-compatible `spawn`；任务仅包含公共密文、证明、公开密钥、参考和授权验证材料。DKG 私有份额、签名身份及不可变批准状态留在主角色进程，RPC 状态锁保留。认证请求/响应均支持磁盘分块拼装、整体摘要、重试幂等及容量/超时限制；解码后的证明对象仍会整体实例化，目前不能声称实现了完整证明的流式验证。

原始依据：[Bulletproofs 原论文](https://web.stanford.edu/~buenz/pubs/bulletproofs.pdf)、[作者实现的范围证明协议](https://github.com/dalek-cryptography/bulletproofs/blob/main/docs/range-proof-protocol.md)、[BIP-340 随机权重批验](https://github.com/bitcoin/bips/blob/master/bip-0340.mediawiki#batch-verification)。最后一项只用于随机权重设计参考，不将其 Schnorr 专用定理直接移植到 DGFlow。

## 15. LegoGroth16 毫秒级完整证明实验后端

`crypto/lego.py` 与当前 `dgfl-native` 提供 `lego_norm_v1` 实验套件。它改变证明系统及设置假设，采用 Dock `legogroth16` 0.18.0。客户端、授权节点、运行管理器及网页已接入；当前所有新加密实验仅接受该套件，`legacy` 等历史方案已退出新实验入口。只有预先安装匹配参数、节点实际加载支持持久参数的原生模块，才能启动 Lego 任务。

数值电路先分配全部 signed `x_j`，再分配范围位及平方中间值。逐坐标约束 `x_j + 2^(bits-1) = sum(2^i * bit_ji)`，各位为 Boolean，最后约束 `sum(x_j^2) = norm`。范数为唯一公开输入，整数上界严格小于群阶，消除模域绕回。650 维、8 位共 6,501 条约束。椭圆曲线密文运算留在曲线群中，无需把 381 位坐标嵌入 255 位标量域电路。

Lego 证明的 `D` 是对前 d 个见证的向量承诺。验证密钥给出公开基底 `Q_j` 和隐藏基底 `Q_v`，满足 `D = sum(Q_j*x_j) + Q_v*v`。完整证明另外保留以下关联关系：

```text
ct_j = F(ctx)*s_j + G*x_j
K_j  = G*s_j + H*k_j
D    = sum(Q_j*x_j) + Q_v*v
```

首消息分别为 `A_ct,j=F*u_j+G*a_j`、`A_K,j=G*u_j+H*w_j` 和 `A_D=sum(Q_j*a_j)+Q_v*xi`。同一 `zx_j=a_j+e*x_j` 同时用于密文及 D 开口；同一 `zs_j=u_j+e*s_j` 同时用于密文及注册密钥；其余响应为 `zk_j=w_j+e*k_j`、`zv=xi+e*v`。先生成完整 Lego 证明及所有首消息，再对完整 ABCD、上下文、客户端、密文、注册密钥、范数、首消息及 CRS 指纹生成独立域分离的非零 Fiat–Shamir 挑战。不存在仅证明另一组明文范围而未绑定实际密文的入口。

完整验证包括 Lego 的数值关系、650 条密文关系、650 条注册密钥关系和一条 D 开口关系；原逐坐标 C 和相应第三条 Sigma 关系由 D 的一次向量开口连接替代。Lego 核心为 240 B（3 个 G1 点和 1 个 G2 点），完整规范二进制证明为 144,777 B，不能将 240 B 描述为整个提交包。所有外部点仍检查曲线、子群和规范字节，所有标量检查域内规范表示。确定性验证逐关系检查；随机验证在完整解析后采独立非零权重，额外批验误接受概率至多 `1/(q-1)`，失败后确定性复查。

`development_setup` 使用 OS 随机源作本地单方设置，返回内存中的 PK/VK，不写设置秘密。`scripts/setup_lego_parameters.py` 将公共证明密钥 PK、验证密钥 VK 和可信清单写入 `runtime/proof-parameters/<crs_hash>/`；可显式离线调用，完整部署也会在服务启动前调用它补齐默认 650/1,930 维、8 位参数，并核验复用已有完整参数。角色启动和实验运行不会自动设置。PK 不是设置陷门。当前设置仅供本机实验，不是多方可信设置仪式，DGFlow 的 DKG 不替代 SNARK 设置。

`crypto/lego_registry.py` 检查清单的电路版本、曲线、维度、位宽、规范密钥长度及文件摘要，再受检加载密钥；任务策略和每轮上下文固定 CRS 指纹。650 维、8 位的 PK 为 1,954,228 B，VK 为 31,692 B。客户端加载本地公共 PK 并在进程内缓存；授权验证子进程只接收主进程从可信清单构造的公共 VK 作业，不接收 PK、DKG 私有份额或签名身份。验证器不采用提交者提供的 VK。原始 VK 不自证其电路位宽，`LegoVerifier.from_bytes(d,bits,VK)` 中的 bits 是可信调用方元数据。当前组合经过代数、恶意输入和内部审查测试，尚未经过密码学外部审计。

`proof_s` 包含整个证明生成调用，`proof_verify_s` 包含整个证明验证调用。离线设置、首次密钥加载和后续缓存读取单独记录，任务总耗时仍包含数据准备期间的首次加载。授权节点的计时通过独立 `proof_metrics` 动作返回，不进入签名决定，避免各节点的计时差异破坏授权 quorum。缺失或不匹配的参数在数据状态写入或 DKG 前拒绝；不回退到其他证明套件。

原生生成器把 Sigma 点计算留在 Rust 中，并一次批量归一化；最多 4 个 Sigma 线程。Lego 的底层 MSM/FFT 在有界 Rayon 池内运行，原生上限为 8，实验使用 4。证明随机数不复用、不进入持久缓存；没有把验证用的公开 G/H 查表用于秘密。Arkworks 证明运算仍是变量时间实现，未声明常数时间。测量记录见[优化报告](../research/optimization-results.md)。

依据：[LegoSNARK 原论文](https://eprint.iacr.org/2019/142.pdf)、[Dock 的承诺见证数据结构](https://github.com/docknetwork/crypto/blob/main/legogroth16/src/data_structures.rs)、[Dock 的证明生成接口](https://github.com/docknetwork/crypto/blob/main/legogroth16/src/prover.rs)。编译实际版本由 `native/dgfl-native/Cargo.lock` 固定。

## 16. 四套证明的实现分层与仅存一处的联动关系

本文前十五节描述**协议规格**；本节描述**代码结构**，因为多个套件并存时，同一关系的重复实现是可靠性风险而不只是整洁问题。

底层 `PROOF_SUITES` 保留四套研究实现：`legacy`、`compact_range_v1`、`compact_norm_v1`、`lego_norm_v1`；这不表示当前新实验入口仍允许四选一。它们各自额外证明不同的陈述（逐位范围／聚合范围／范围加平方范数／SNARK 范数），但**都要证明同一条逐坐标联动关系**：`ct_j` 与已登记密钥 `K_j` 使用同一加密标量 `s_j`，且 `ct_j` 中的 `x_j` 就是附加陈述所约束的那个值。

该联动的首消息、响应与残差由 `crypto/linkage.py` **单一实现**，被三个 Python 路径调用：

| 位置 | 复用的部分 |
| --- | --- |
| `protocol.py`（legacy） | `first_messages`、`responses`、`add_equations`，另加 C/D 两条方程与逐位 OR |
| `protocol.py`（compact） | 同上三者，另加 C 一条方程，块证明由 `compact.py`/`ipa.py` 承担 |
| `lego.py` | `responses`、`add_equations`；**首消息不在此列**，见下 |

Lego 的逐坐标首消息由 `dgfl_native.sigma_first_messages` 在 Rust 中批量生成（见第 15 节的性能记录）。该路径刻意**不**改写为共用 `linkage.first_messages`：它是实测的快速路径，且改动原生接口会改变性能基线。因此边界是：**方程构造在所有套件中单一来源；首消息生成在 legacy/compact 共用，Lego 走原生。**

`tests/crypto/test_linkage.py` 把该联动当作独立 Σ 协议验证完备性与拒绝行为，并含一条防回退断言：两条残差方程的系数模式只允许出现在 `linkage.py`，任何套件重新内联即失败。

改动联动或其覆盖套件时的验收方法：证明是随机化的，两次生成不可逐字节比较，因此**不能**靠比对证明字节判断行为是否保持。做法是先冻结重构前各套件生成的完整证明，重构后要求新验证器**接受每份冻结证明并拒绝其篡改版本**（验证是冻结字节的确定性函数）。该跨版本检查与单元测试互补，两者都通过才视为行为保持。

## 17. 2026-10-04：部分解密正确性证明

新增 `DGFL-AGGREGATE-PAIRING-V1`，对全部四种客户端证明套件强制执行。旧的仅签名 `D/E` 结果不能被新合并器接受。签名认证身份；以下证明额外约束实际的配对指数。

authority a 对批准集合的第 j 个坐标建立次数为 `cloud_threshold-1` 的秘密多项式 `h_aj(X)` 与独立盲化多项式 `r_aj(X)`，公开系数承诺 `C_ajk=G*h_ajk+H*r_ajk`。其常数项承诺必须等于**已确认且带身份签名的原 DKG 转录**在 a 处的份额承诺，按批准客户端求和。验证器从该转录重算常数承诺，拒绝提交者自行替换的函数密钥。不同云必须引用同一 authority 集合及同一组多项式承诺。

令 `T=e(F(ctx),G2)`、`s=h_aj(t)`、`r=r_aj(t)`、`C(t)=sum(t^k*C_ajk)`。authority 知道 s/r，而云只收到私有 `G2*s`，因此由 authority 对每个云份额生成联合表示证明：

```text
E_atj = T^s
A_atj = G*u + H*v
B_atj = T^u
c = FS(suite, context_hash, epoch, manifest_hash, transcript_hash,
       authority_id, cloud_id, cloud_threshold, approved,
       all polynomial commitments, all E, all A, all B)
zs = u + c*s; zr = v + c*r

Verify: G*zs + H*zr = A_atj + c*C(t)
        T^zs       = B_atj * E_atj^c
```

全部点、GT 和标量采用受检规范编码；每坐标的两个方程确定性验证，首消息使用独立 OS 随机数。签名证书及证明连同 G2 函数钥**先密封给对应云**，云发布其部分解密时才公开证书。coordinator 不能通过公开 authority 动作提前取得任意两个云的配对像；私有 G2 函数钥和标量不公开。

2026-10-05 的可选 `PublicAggregateVerifier` 将受检批解码、多项式求值和全部逐坐标方程放入一次 Rust 调用。调用内多项式句柄绑定 G/H/T；Python 继续绑定 authority、轮次、清单、公共 DKG 转录及 Fiat–Shamir 挑战，缓存命中仍对照当前 DKG 常数。公开 T 的四位预计算表只处理公开验证响应，不用于秘密份额或证明随机数。默认每个合并进程一个原生工作线程；四个独立合并与确认均保留。证明字节、方程、电路与 CRS 均不改变，缺少新 API 时使用保留的 Python 参考核验路径。

该核验器的 GT 解码先保留规范编码和非零检查，再用精确关系 `Frob4(x) * x == Frob2(x)` 检查 cyclotomic 子群归属，随后检查 `Frob1(x) == inverse(x^abs(X))`，其中 X 为 BLS12-381 的固定负参数。在阶为 `p^4−p²+1` 的 cyclotomic 群内，后者等价于 `x^(p+abs(X)) == 1`；固定参数满足 `gcd(p^4−p²+1, p+abs(X)) == q`，因此两项合取与完整 q 阶成员检查等价。快速 cyclotomic 指数只能在前置归属检查成立后使用，不能用较弱的 unitary 条件替代；公开 `E` 的指数同样只处理已完成 GT 子群检查的元素。随机域元素、unitary 但非 cyclotomic 元素、cyclotomic 但非 q 阶元素及合法 GT 均与原通用 `pow(q)` 对照，接受集合保持一致。通用 `NativeGT` 解码与秘密生成运算未改变。

云按 authority 门限插值得到 E。合并器独立核验 authority 证书、DKG 常数承诺和上述证明，再重算预期云 E 并与该云实际 E 比较；同时直接从批准密文重新计算 D。`combine` 必须接收由可信调用方认证过的 `verification_materials` 和批准的 `packets`，省略即拒绝。authority 的完成动作使用自己的固定 DKG 转录与批准密文，不能由 coordinator 替换其校验基准。

回归测试包含合法云身份签名下把 17 改成 7 的原攻击、有效但非 DKG 密钥的自行构造证明、响应/配对钥/上下文/转录篡改、所有云一起伪造 D、云间多项式分叉，以及剔除坏云后另一诚实门限对子恢复 17。遇到坏部分结果当前任务中止；自动定位并重试诚实子集、拜占庭 DKG、完整跨层串谋归约和外部密码审计仍未实现。
